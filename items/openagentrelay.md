# OpenAgentRelay

## 一句话总结

一个把受限的本地 Agent 或自动化命令变成可信局域网可调用能力的开源 CLI，同时让源码、提示词、依赖与凭据继续留在发布端。

## 快速判断

- 如果你想让队友或另一个 Agent 调用一项本地能力，但不想复制整套环境与敏感配置，它值得关注
- 如果你需要公网服务、企业级身份认证或成熟的生产网关，当前 Alpha 版本并不适合
- 它更像轻量的本地能力中继层，而不是模型 API 代理、MCP Server 或完整多 Agent 编排平台

## 你会怎么用它

- 发布本地能力：把一个受限的 Claude Code、Codex、脚本或自动化命令包装成可调用的 capability
- 团队内调用：通过共享密钥和可信局域网，让队友或其他 Agent 发起一次请求并读取结构化结果
- 保留本地边界：发布方继续掌握源码、提示词、依赖、工作目录和凭据，不需要把整套项目交给调用方

## 它解决什么问题

- 一项 Agent 能力依赖本地代码、私有提示词或复杂环境，复制给每个协作者成本很高
- 团队希望复用本地 Agent 或自动化，但不希望调用者直接接触底层凭据与实现细节
- 临时用 SSH、聊天消息或手工转发任务时，调用方式、结果格式和退出状态都不稳定

## 适合谁

- 想在可信局域网内共享本地 Agent 能力的开发者和小团队
- 需要把 Claude Code、Codex 或其他命令式 Agent 接进内部自动化链路的人
- 希望先用轻量 CLI 验证 Agent-to-Agent 能力调用，而不是立即部署完整平台的团队

## 核心能力

- 能力发布：把本地 Agent 或自动化命令注册并启动为可调用 capability
- 结构化调用：`relay ask --json` 可输出机器可读结果，便于接进脚本和其他 Agent
- 调用约束：支持 `--expect-agent`、有意义的退出码和有界会话，减少自动化误判
- 本地优先：发布方的源码、提示词、依赖和凭据保持在原环境中
- 简单鉴权：当前使用共享密钥，适合受信任的局域网实验与内部协作

## 能力边界

- 明显可用：可信局域网内的原型验证、小团队共享、受限命令调用和 Agent 间轻量协作
- 效果一般：需要复杂调度、任务队列、细粒度权限或跨组织治理的场景
- 不要误用：当前 Alpha 版本不建议暴露到公网，也不应直接承接生产写操作

## 集成方式

- 作为单独工具：在发布端配置受限命令并启动 relay，在调用端通过 CLI 发起请求
- 作为 Agent 工具：把项目链接和调用说明交给 Codex、Claude Code 或其他 Agent，让它使用已有 capability
- 作为自动化节点：使用 JSON 输出和退出码，把一次 capability 调用接入 shell 脚本、CI 或内部工作流

## 上手建议

- 第一步只发布一个只读、低风险且输入边界清晰的命令
- 先在可信局域网内验证共享密钥、超时、失败退出码和结果解析
- 等权限、审计与部署需求明确后，再决定是否需要更完整的 Agent 平台或网关

## 选型建议

- 如果主需求是“让其他人或 Agent 调用我机器上的一项受限能力”，它的定位很直接
- 如果主需求是模型供应商路由、用量管理或 OpenAI 兼容 API，应该看专门的模型网关
- 如果主需求是多 Agent 任务拆分、调度和状态管理，应该看完整的编排框架

## 为什么值得关注

- 它把“分享能力”和“分享整套项目环境”拆开，降低团队复用本地 Agent 的门槛
- CLI、JSON 输出与退出码让能力既能给人调用，也能被其他 Agent 和脚本稳定消费
- 项目明确限制在可信局域网和低风险场景，当前能力边界比较清楚
